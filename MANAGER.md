# Подключение менеджера к заявкам MAX

Сейчас уведомления сайта приходят одному подтверждённому получателю в личный чат. Подключение менеджера **заменяет** этого получателя. Чтобы сохранить уведомления владельцу и одновременно отправлять менеджерам, сначала нужно добавить несколько получателей в интеграцию. Эта инструкция не меняет действующего получателя автоматически.

## Что делает менеджер

1. Открывает бота [fullerene.pro](https://max.ru/se14310383_1_bot) в MAX.
2. Нажимает **«Начать»**.
3. Получает одноразовый код от владельца сайта и отправляет в этот бот одним сообщением команду `/connect КОД`. Реальный код генерирует владелец; слово «КОД» отправлять не нужно.
4. После подтверждения привязки владельцем и настройки сервера получает новые заявки: имя, телефон и выбранный вариант связи — **телефон или MAX**. По номеру связывается с клиентом, отметку об обработке ведёт в админ-панели сайта.
5. Проверяет, что уведомления от бота включены в MAX и в настройках телефона.

Токен бота, `.env`, пароль сервера и доступ к GitHub менеджеру не нужны. Одного нажатия «Начать» недостаточно для назначения получателем заявок.

## Что делает владелец или администратор

В папке бота с актуальным закрытым `.env`:

```powershell
cd C:\projects\fenix\fenix_max
npm run manager:prepare
```

Команда проверяет бота и выводит готовую `/connect ...`. Передайте её только назначенному менеджеру. Код действует **30 минут**. Генерация кода пока не меняет текущего получателя.

После сообщения менеджера:

```powershell
npm run manager:confirm
```

Подтверждение принимает только точное сообщение с одноразовым кодом из личного диалога с настоящим пользователем. В локальном `.env` обновляется `MAX_USER_ID`, `MAX_CHAT_ID` очищается. Если сообщение ещё не найдено, повторите команду. Если срок истёк — создайте новый код. Если бот уже использует webhook, помощник останавливается и не удаляет существующую подписку.

**Эти команды обновляют только локальную конфигурацию. Чтобы заявки опубликованного сайта пошли менеджеру, администратор должен обновить получателя на REG.RU.**

У работающего сайта путь к текущей приватной конфигурации определяется так:

1. По SSH прочитать `/var/www/u3614324/data/.fenix-private/current-release` — имя действующего выпуска.
2. Открыть `/var/www/u3614324/data/.fenix-releases/<имя-выпуска>/private/config.json` через защищённый SFTP/SSH, вне публичного корня сайта.
3. Сделать приватную резервную копию файла. Из локального `.env` перенести только подтверждённое значение `MAX_USER_ID`; `MAX_CHAT_ID` оставить пустым. Остальные поля и действующий токен сохранить. Не отправлять конфигурацию в чат и не добавлять её в Git.
4. Сохранить файл с правами `600`. Перезапуск сайта не требуется: конфигурация читается при отправке.
5. Отправить одну явно обозначенную техническую заявку через сайт и проверить получение менеджером. После успешной проверки техническую запись удалить через админ-панель. Реальные заявки не удалять.

Обновление серверной конфигурации также можно поручить мне после отправки менеджером команды. До этого действующий чат владельца продолжает получать заявки.

## Если уведомление не пришло

Сначала убедитесь, что менеджер нажал «Начать», отправил именно выданную команду и сервер использует его подтверждённый `MAX_USER_ID`. Проверьте включённые уведомления MAX. При недоступности API заявка сохраняется, очередь повторяет доставку. Статус отправки и ручной повтор доступны в админ-панели сайта.
