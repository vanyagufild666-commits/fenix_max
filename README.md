# Fenix MAX

[Инструкция подключения менеджера](MANAGER.md).

Бот уведомлений о заявках «Феникс Плюс» для личного чата MAX. В сообщении указаны имя, телефон, город, способ связи **телефон / MAX**, запрос на трансфер и страница обращения. Отправляется уведомление с `notify: true`.

В репозитории находится модуль доставки из работающего сайта: `runtime/max-notifications.php` совпадает с опубликованной версией сайта в коммите `176e89e3c2d400205eccb754b843ef9842b81c6c`. Добавлены отдельный запуск, конфигурация через `.env` и изолированные проверки. Бот на REG.RU уже подключён; его работа не требует запуска этой локальной копии.

## Локальная конфигурация и запуск

Нужны PHP 8.2+ с `curl`, `pdo_sqlite`, `sqlite3`; для npm-команд — Node.js 24+. Сторонние зависимости устанавливать не нужно.

```sh
cp .env.example .env
# Указать MAX_BOT_TOKEN и подтверждённый MAX_USER_ID только в .env
npm run check
npm test
npm start
```

На подготовленном компьютере актуальный `.env` уже заполнен. `PHP_BINARY` указывает на имеющийся PHP. Локальная очередь `data/site.sqlite` отдельная и первоначально пустая; проверка `npm run check` только проверяет подключение, сообщений не отправляет.

```sh
npm run dispatch   # обработать до 20 записей и завершить работу
```

Также можно вызвать напрямую `php runtime/worker.php --once`, `--loop` или `--check`. Перед публикацией: `npm run check:secrets`.

## Подключение к сайту и REG.RU

Сайт сохраняет заявку и запись `outbox` в одной транзакции. Этот worker читает **ту же SQLite-базу сайта**; отдельного публичного API и входящего webhook ему не требуется. `runtime/migration.sql` содержит совместимую структуру очереди. Не копируйте рабочую базу или заявки в Git.

Для REG.RU укажите в закрытом `.env`:

```dotenv
DATABASE_PATH=/var/www/u3614324/data/.fenix-private/data/site.sqlite
PHP_BINARY=/usr/bin/php
```

Размещайте папку бота **вне публичного корня сайта**, ограничьте права папки и `.env` (`700` / `600`). Можно использовать cron раз в минуту:

```cron
* * * * * /usr/bin/php /PRIVATE/BOT/runtime/worker.php --once >> /PRIVATE/BOT/data/worker.log 2>&1
```

На сервере уже работают отправка после ответа формы и cron сайта. При отдельной установке этот worker может заменить существующий cron; не нужно менять работающую установку ради хранения кода в другом репозитории. Блокировка общей SQLite-записи защищает от одновременной отправки одной заявки; сетевой сбой после принятия сообщения MAX может привести к повтору с тем же ID заявки.

## Доставка и безопасность

Запись резервируется до сетевого запроса, затем подтверждается квитанцией `message.body.mid`. При сбое запись остаётся в очереди; повтор через минуту, до пяти попыток. Прерванная отправка подбирается через две минуты. Логи не содержат имён, телефонов, токенов или ID получателя.

`MAX_USER_ID` имеет приоритет над `MAX_CHAT_ID`. Настроенный личный получатель не подменяется группой при ошибке конфигурации. `.env`, базы и журналы исключены из Git; `.env.example` содержит только пустые поля и публичные настройки.

Используется официальный API `https://platform-api2.max.ru`. TLS-проверка включена; публичный корневой сертификат применяется только для этого точного хоста. [API отправки сообщений MAX](https://dev.max.ru/docs-api/methods/POST/messages).

Тесты используют отдельную временную SQLite-базу, вымышленные данные и подмену транспортного запроса. Они не отправляют сообщения настоящему боту.
